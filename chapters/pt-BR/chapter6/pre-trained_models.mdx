# Modelos pré-treinados para síntese de fala a partir de texto

Há significativamente menos checkpoints pré-treinados para TTS que para ASR e classificação de áudio. No 🤗 Hub, você encontrará cerca de 300 opções adequadas. Entre elas, vamos nos concentrar em duas arquiteturas disponíveis em 🤗 Transformers: SpeechT5 e Massive Multilingual Speech (MMS). Nesta seção, veremos como usá-las para TTS.

## SpeechT5

[SpeechT5](https://arxiv.org/abs/2110.07205) é um modelo publicado por Junyi Ao e outros autores da Microsoft, capaz de executar várias tarefas de fala. Aqui, focamos a síntese a partir de texto, mas ele pode ser adaptado para tarefas de fala para texto, como reconhecimento automático de fala ou identificação de falante, e de fala para fala, como melhoria do áudio ou conversão entre vozes. Isso é possível graças ao seu projeto e pré-treinamento.

No centro de SpeechT5 há um modelo transformer codificador-decodificador convencional. Como em outros transformers, essa rede modela uma transformação de sequência a sequência por representações ocultas. A estrutura central é a mesma para todas as tarefas suportadas.

Ela é complementada por seis _pré-redes_ e _pós-redes_ específicas para cada modalidade, fala ou texto. A entrada passa pela pré-rede correspondente para produzir representações ocultas utilizáveis pelo transformer. A saída passa pela pós-rede, que gera o resultado na modalidade desejada.

A arquitetura é esta, em uma imagem do artigo original:

<div class="flex justify-center">
    <img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/speecht5/architecture.jpg" alt="Arquitetura de SpeechT5 no artigo original">
</div>

SpeechT5 primeiro é pré-treinado em grandes quantidades de fala e texto não rotulados para obter uma representação unificada das modalidades. Todas as pré-redes e pós-redes são usadas simultaneamente nessa fase.

Depois, toda a estrutura codificador-decodificador é ajustada para cada tarefa individual. Só são usadas as pré-redes e pós-redes relevantes. Para TTS, por exemplo, precisamos da pré-rede do codificador de texto para as entradas e das pré-redes e pós-redes do decodificador de fala para as saídas.

Essa abordagem permite obter vários modelos ajustados para diferentes tarefas, todos beneficiados pelo pré-treinamento inicial em dados não rotulados.

<Tip>

Embora os modelos ajustados comecem com os mesmos pesos do modelo pré-treinado compartilhado, suas versões finais são bastante diferentes. Não é possível trocar as pré-redes e pós-redes de um modelo ASR ajustado e obter um modelo TTS funcional, por exemplo. SpeechT5 é flexível, mas não tanto assim ;)

</Tip>

Para TTS, as redes usadas são:

* Pré-rede do codificador de texto: uma camada de embeddings que mapeia tokens de texto para as representações ocultas esperadas pelo codificador, como em modelos NLP como BERT.
* Pré-rede do decodificador de fala: recebe um espectrograma log-mel e usa uma sequência de camadas lineares para comprimi-lo em representações ocultas.
* Pós-rede do decodificador de fala: prevê um resíduo a ser acrescentado ao espectrograma de saída para refinar os resultados.

Combinando-as, temos esta arquitetura de TTS:

<div class="flex justify-center">
    <img src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/speecht5/tts.jpg" alt="Arquitetura de SpeechT5 para TTS">
</div>

A saída é um espectrograma log-mel, não a forma de onda final. Abordamos isso brevemente na [unidade 3](../chapter3/introduction#saída-de-espectrograma). É comum modelos de geração de áudio produzirem espectrogramas log-mel, que precisam ser convertidos em formas de onda por uma rede neural adicional chamada vocoder.

Vamos ver como fazer isso.

Primeiro, carregamos o modelo SpeechT5 ajustado para TTS do 🤗 Hub e o processador usado na tokenização e extração de características:

```python
from transformers import SpeechT5Processor, SpeechT5ForTextToSpeech

processor = SpeechT5Processor.from_pretrained("microsoft/speecht5_tts")
model = SpeechT5ForTextToSpeech.from_pretrained("microsoft/speecht5_tts")
```

Em seguida, tokenizamos a entrada:

```python
inputs = processor(text="Don't count the days, make the days count.", return_tensors="pt")
```

SpeechT5 não se limita a gerar fala de uma única pessoa. Ele usa embeddings de falante que capturam as características de uma voz específica.

<Tip>

Embeddings de falante representam a identidade de uma pessoa de forma compacta, com um vetor de tamanho fixo, independentemente da duração do enunciado. Capturam informações essenciais sobre voz, sotaque, entonação e outras características que distinguem falantes. Podem ser usados em verificação de falante, diarização, identificação e outras tarefas.

As técnicas mais comuns incluem:

* I-Vectors, ou vetores de identidade: baseados em modelos de mistura gaussiana (GMM). Representam falantes por vetores fixos de baixa dimensão derivados das estatísticas de um GMM específico da pessoa, obtidos sem supervisão.
* X-Vectors: derivados de redes neurais profundas (DNNs), capturam informações de falante por quadro, incorporando contexto temporal.

[X-Vectors](https://www.danielpovey.com/files/2018_icassp_xvectors.pdf) são um método do estado da arte com desempenho superior ao de I-Vectors nos conjuntos de avaliação. A rede profunda aprende a distinguir falantes e mapeia enunciados de duração variável para embeddings de dimensão fixa. Você também pode carregar um X-Vector calculado previamente, que representa as características de fala de uma pessoa.

</Tip>

Vamos carregar esse tipo de embedding de um conjunto no Hub. Eles foram obtidos do [CMU ARCTIC](http://www.festvox.org/cmu_arctic/) com [este script](https://huggingface.co/mechanicalsea/speecht5-vc/blob/main/manifest/utils/prep_cmu_arctic_spkemb.py), mas qualquer embedding X-Vector deve funcionar.

```python
from datasets import load_dataset

embeddings_dataset = load_dataset("Matthijs/cmu-arctic-xvectors", split="validation")

import torch

speaker_embeddings = torch.tensor(embeddings_dataset[7306]["xvector"]).unsqueeze(0)
```

O embedding é um tensor de formato (1, 512). Este, especificamente, descreve uma voz feminina.

Já temos as entradas necessárias para gerar um espectrograma log-mel:

```python
spectrogram = model.generate_speech(inputs["input_ids"], speaker_embeddings)
```

A saída é um tensor de formato (140, 80). A primeira dimensão é o comprimento da sequência, que pode variar entre execuções porque a pré-rede do decodificador de fala sempre aplica dropout à entrada. Isso introduz uma pequena variabilidade aleatória na fala gerada.

Para gerar uma forma de onda, precisamos especificar um vocoder para converter o espectrograma. Em teoria, qualquer vocoder que trabalhe com espectrogramas mel de 80 faixas pode servir. 🤗 Transformers oferece um baseado em HiFi-GAN, cujos pesos foram gentilmente fornecidos pelos autores de SpeechT5.

<Tip>

[HiFi-GAN](https://arxiv.org/pdf/2010.05646v2.pdf) é uma rede adversarial generativa (GAN) do estado da arte para síntese de fala de alta fidelidade. Ela gera formas de onda realistas e de alta qualidade a partir de espectrogramas.

Em linhas gerais, tem um gerador e dois discriminadores. O gerador é uma rede totalmente convolucional que recebe um espectrograma mel e aprende a produzir formas de onda brutas. Os discriminadores distinguem áudio real de áudio gerado, concentrando-se em aspectos diferentes.

HiFi-GAN é treinado em um grande conjunto de gravações de alta qualidade com <em>treinamento adversarial</em>, em que gerador e discriminadores competem. Inicialmente, o gerador produz áudio ruim, facilmente distinguido do real. Ao longo do treinamento, melhora a saída para enganar o discriminador, que também melhora sua capacidade de distinguir áudio real e gerado. Esse ciclo de feedback ajuda ambas as redes a melhorar. Ao final, HiFi-GAN aprende a gerar áudio de alta fidelidade com características próximas às dos dados de treinamento.

</Tip>

Carregar o vocoder é tão simples quanto carregar qualquer modelo de 🤗 Transformers:

```python
from transformers import SpeechT5HifiGan

vocoder = SpeechT5HifiGan.from_pretrained("microsoft/speecht5_hifigan")
```

Basta passá-lo como argumento na geração de fala para converter automaticamente as saídas em formas de onda:

```python
speech = model.generate_speech(inputs["input_ids"], speaker_embeddings, vocoder=vocoder)
```

Vamos ouvir o resultado. A taxa de amostragem de SpeechT5 é sempre de 16 kHz.

```python
from IPython.display import Audio

Audio(speech, rate=16000)
```

## Bark

Bark é um modelo TTS baseado em transformers, proposto pela Suno AI em [suno-ai/bark](https://github.com/suno-ai/bark).

Diferentemente de SpeechT5, ele gera formas de onda brutas diretamente, dispensando um vocoder separado na inferência: esse componente já está integrado. Isso é possível com [`Encodec`](https://huggingface.co/docs/transformers/main/en/model_doc/encodec), que funciona como codec e ferramenta de compressão.

Com `Encodec`, podemos comprimir áudio em um formato leve para reduzir o uso de memória e depois descomprimi-lo para restaurar o áudio original. A compressão usa 8 dicionários de códigos, ou codebooks, compostos de vetores de inteiros. Pense neles como representações ou embeddings do áudio em forma inteira. Cada dicionário sucessivo melhora a qualidade da reconstrução dos anteriores. Como são vetores de inteiros, podem ser aprendidos por transformers, muito eficientes nessa tarefa. Bark foi treinado especificamente para isso.

Bark é composto de 4 modelos principais:

- `BarkSemanticModel`, ou modelo de "texto": um transformer causal autorregressivo que recebe texto tokenizado e prevê tokens semânticos que capturam seu significado.
- `BarkCoarseModel`, ou modelo de "acústica grosseira": um transformer causal autorregressivo que recebe os resultados de `BarkSemanticModel` e prevê os dois primeiros dicionários de códigos de áudio necessários a EnCodec.
- `BarkFineModel`, ou modelo de "acústica fina": um transformer autocodificador não causal que prevê iterativamente os últimos dicionários a partir da soma dos embeddings dos anteriores.
- Depois de prever todos os canais dos dicionários de `EncodecModel`, Bark usa esse modelo para decodificar o array de áudio de saída.

Os três primeiros módulos suportam embeddings condicionais de falante para condicionar o som a uma voz predefinida específica.

Bark permite bastante controle: podemos usá-lo com várias configurações, como veremos.

Primeiro, carregamos modelo e processador.

O processador tem duas funções:

1. Tokenizar o texto, dividindo-o em partes pequenas que o modelo entende.
2. Armazenar embeddings de falante, ou configurações predefinidas de voz, que condicionam a geração.

```python
from transformers import BarkModel, BarkProcessor

model = BarkModel.from_pretrained("suno/bark-small")
processor = BarkProcessor.from_pretrained("suno/bark-small")
```

Bark é versátil e pode gerar áudio condicionado por uma [biblioteca de embeddings de falante](https://suno-ai.notion.site/8b8e8749ed514b0cbf3f699013548683?v=bc67cff786b04b50b3ceb756fd05f68c), carregada pelo processador.

```python
# add a speaker embedding
inputs = processor("This is a test!", voice_preset="v2/en_speaker_3")

speech_output = model.generate(**inputs).cpu().numpy()
```

## Massive Multilingual Speech (MMS)

Se você procura um modelo pré-treinado em outro idioma, Massive Multilingual Speech (MMS) também executa diversas tarefas de fala e suporta muitos idiomas. Por exemplo, sintetiza fala em mais de 1.100 idiomas.

MMS para TTS é baseado em [VITS, de Kim e outros autores, 2021](https://arxiv.org/pdf/2106.06103.pdf), uma das abordagens do estado da arte.

VITS é uma rede que converte texto em formas de onda brutas. Funciona como um autocodificador variacional condicional, estimando características de áudio a partir do texto. Primeiro, gera características acústicas representadas como espectrogramas. Depois, decodifica a forma de onda com camadas convolucionais transpostas adaptadas de HiFi-GAN. Na inferência, aumenta a resolução das codificações de texto e as transforma em formas de onda com o módulo de fluxo e o decodificador HiFi-GAN. Assim como Bark, dispensa vocoder separado, pois gera formas de onda diretamente.

<Tip warning={true}>

MMS foi adicionado a 🤗 Transformers muito recentemente, então você precisará instalar a biblioteca a partir do código-fonte:

```bash
pip install git+https://github.com/huggingface/transformers.git
```

</Tip>

Vamos experimentar MMS para sintetizar fala em outro idioma, como alemão. Primeiro, carregamos checkpoint e tokenizador do idioma correto:

```python
from transformers import VitsModel, VitsTokenizer

model = VitsModel.from_pretrained("facebook/mms-tts-deu")
tokenizer = VitsTokenizer.from_pretrained("facebook/mms-tts-deu")
```

Para carregar MMS, usamos `VitsModel` e `VitsTokenizer`, pois a versão TTS é baseada em VITS, como explicado.

Escolheremos um texto em alemão, como estas duas primeiras linhas de uma canção infantil:

```python
text_example = (
    "Ich bin Schnappi das kleine Krokodil, komm aus Ägypten das liegt direkt am Nil."
)
```

Para gerar a forma de onda, pré-processamos o texto com o tokenizador e o passamos ao modelo:

```python
import torch

inputs = tokenizer(text_example, return_tensors="pt")
input_ids = inputs["input_ids"]


with torch.no_grad():
    outputs = model(input_ids)

speech = outputs["waveform"]
```

Vamos ouvir:

```python
from IPython.display import Audio

Audio(speech, rate=16000)
```

Wunderbar! Para experimentar outro idioma, procure checkpoints `vits` adequados [no 🤗 Hub](https://huggingface.co/models?filter=vits).
