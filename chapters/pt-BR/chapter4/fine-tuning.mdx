# Ajuste fino de um modelo para classificação de música

Nesta seção, veremos passo a passo como fazer o ajuste fino de um transformer com apenas codificador para classificar música. Usaremos um modelo leve e um conjunto de dados relativamente pequeno, permitindo executar todo o código em qualquer GPU de uso doméstico, inclusive a T4 de 16 GB da versão gratuita do Google Colab. A seção também traz dicas para quem tem uma GPU menor e encontra problemas de memória.

## O conjunto de dados

Para treinar nosso modelo, usaremos o [GTZAN](https://huggingface.co/datasets/marsyas/gtzan), um conjunto popular de 1.000 músicas para classificação de gêneros musicais. Cada música é um trecho de 30 segundos de um dos 10 gêneros, que vão de disco a metal. Podemos obter os arquivos e seus rótulos do Hugging Face Hub com `load_dataset()` de 🤗 Datasets:

## Escolha de um modelo pré-treinado para classificação de áudio

Começaremos escolhendo um modelo adequado. Nesse campo, o pré-treinamento costuma usar grandes quantidades de áudio não rotulado, com conjuntos como [LibriSpeech](https://huggingface.co/datasets/librispeech_asr) e [Voxpopuli](https://huggingface.co/datasets/facebook/voxpopuli). A melhor maneira de encontrar esses modelos no Hub é o filtro "Audio Classification", descrito na seção anterior. Embora Wav2Vec2 e HuBERT sejam populares, usaremos _DistilHuBERT_, uma versão muito menor, ou _destilada_, do [HuBERT](https://huggingface.co/docs/transformers/model_doc/hubert). Ela treina cerca de 73% mais rápido, preservando a maior parte do desempenho.

## Do áudio às características de aprendizado de máquina

## Pré-processamento dos dados

Assim como a tokenização em NLP, modelos de áudio e fala precisam que a entrada seja codificada em um formato que possam processar. Em 🤗 Transformers, essa conversão é feita pelo _extrator de características_ do modelo. Como ocorre com tokenizadores, a classe `AutoFeatureExtractor` seleciona automaticamente o extrator correto para cada modelo. Para processar nossos arquivos, vamos instanciar o extrator de características do DistilHuBERT a partir do checkpoint pré-treinado:

```python
from transformers import AutoFeatureExtractor

model_id = "ntu-spml/distilhubert"
feature_extractor = AutoFeatureExtractor.from_pretrained(
    model_id, do_normalize=True, return_attention_mask=True
)
```

Como o modelo e o conjunto de dados têm taxas de amostragem diferentes, precisamos reamostrar o áudio para 16.000 Hz antes de passá-lo ao extrator. Primeiro, obtemos a taxa esperada pelo modelo a partir do extrator:

```python
sampling_rate = feature_extractor.sampling_rate
sampling_rate
```

**Saída:**
```out
16000
```

Em seguida, reamostramos o conjunto com `cast_column()` e o recurso `Audio` de 🤗 Datasets:

```python
from datasets import Audio

gtzan = gtzan.cast_column("audio", Audio(sampling_rate=sampling_rate))
```

Podemos conferir a primeira amostra da divisão de treinamento para verificar que sua taxa é de 16.000 Hz. 🤗 Datasets reamostra o arquivo _sob demanda_ quando carregamos cada exemplo:

Ótimo! A taxa foi reduzida para 16 kHz. Os valores do array também mudaram, pois agora temos aproximadamente um valor de amplitude para cada 1,5 valor anterior.

Uma característica de modelos como Wav2Vec2 e HuBERT é receberem um array de ponto flutuante correspondente à forma de onda bruta da fala. Isso difere de modelos como Whisper, nos quais pré-processamos a forma de onda para obter um espectrograma.

Como o áudio já é representado por um array unidimensional, ele está no formato correto para o modelo: entradas contínuas em instantes discretos. O que o extrator de características faz, então?

Os dados têm o formato correto, mas ainda não impusemos limites a seus valores. Para o modelo funcionar bem, queremos manter todas as entradas na mesma faixa dinâmica. Assim, obtemos faixas semelhantes de ativações e gradientes entre os exemplos, ajudando na estabilidade e na convergência do treinamento.

Para isso, _normalizamos_ o áudio, reescalando cada exemplo para média zero e variância unitária, um processo chamado _escalonamento de características_. É exatamente essa normalização que o extrator realiza!

Vamos observá-lo funcionando no primeiro exemplo de áudio. Primeiro, calculamos a média e a variância do áudio bruto:

```python
import numpy as np

sample = gtzan["train"][0]["audio"]

print(f"Mean: {np.mean(sample['array']):.3}, Variance: {np.var(sample['array']):.3}")
```

**Saída:**
```out
Mean: 0.000185, Variance: 0.0493
```

A média já está próxima de zero, mas a variância está mais próxima de 0,05. Se a variância do exemplo fosse maior, isso poderia causar problemas ao modelo, pois a faixa dinâmica dos dados de áudio seria muito pequena e, portanto, difícil de separar. Vamos aplicar o extrator e examinar a saída:

```python
inputs = feature_extractor(sample["array"], sampling_rate=sample["sampling_rate"])

print(f"inputs keys: {list(inputs.keys())}")

print(
    f"Mean: {np.mean(inputs['input_values']):.3}, Variance: {np.var(inputs['input_values']):.3}"
)
```

**Saída:**
```out
inputs keys: ['input_values', 'attention_mask']
Mean: -4.53e-09, Variance: 1.0
```

O extrator retorna um dicionário com dois arrays: `input_values` e `attention_mask`. O primeiro contém o áudio pré-processado que passaremos ao HuBERT. A [`attention_mask`](https://huggingface.co/docs/transformers/glossary#attention-mask) é usada ao processar um _lote_ de áudios de uma vez, indicando ao modelo onde adicionamos preenchimento a entradas de comprimentos diferentes.

Agora a média está muito mais próxima de zero e a variância é exatamente um! Esse é o formato desejado antes de fornecer as amostras ao HuBERT.

<Tip warning={true}>

Observe que passamos a taxa de amostragem do áudio ao extrator. É uma boa prática, pois ele confere internamente se essa taxa corresponde à esperada pelo modelo. Se fossem diferentes, precisaríamos aumentar ou reduzir a taxa do áudio para a correta.

</Tip>

Agora sabemos processar o áudio reamostrado. Falta definir uma função aplicável a todos os exemplos. Como esperamos trechos de 30 segundos, também truncaremos os mais longos com os argumentos `max_length` e `truncation`:

```python
max_duration = 30.0


def preprocess_function(examples):
    audio_arrays = [x["array"] for x in examples["audio"]]
    inputs = feature_extractor(
        audio_arrays,
        sampling_rate=feature_extractor.sampling_rate,
        max_length=int(feature_extractor.sampling_rate * max_duration),
        truncation=True,
        return_attention_mask=True,
    )
    return inputs
```

Podemos aplicar essa função ao conjunto pelo método [`map()`](https://huggingface.co/docs/datasets/v2.14.0/en/package_reference/main_classes#datasets.Dataset.map). Ele permite trabalhar com lotes de exemplos, o que ativaremos com `batched=True`. O tamanho padrão do lote é 1000, mas usaremos 100 para manter o pico de uso de RAM adequado à versão gratuita do Colab:

<!--- TODO(SG): voltar ao multiprocessamento quando o bug de datasets for corrigido.

Para simplificar o treinamento, removemos as colunas `audio` e `file`. A coluna `input_values` contém o áudio codificado; `attention_mask` é uma máscara binária de zeros e uns indicando o preenchimento; `genre` contém os rótulos, ou alvos. Para que `Trainer` processe os rótulos, precisamos renomear `genre` para `label`:

```python
gtzan_encoded = gtzan_encoded.rename_column("genre", "label")
```

Por fim, obtemos os mapeamentos de rótulos do conjunto. Eles convertem identificadores inteiros, como `7`, em rótulos legíveis, como `"pop"`, e vice-versa. Assim, podemos converter as previsões inteiras do modelo para um formato legível e usá-lo em qualquer aplicação posterior. Para isso, usamos `int2str()`:

```python
id2label = {
    str(i): id2label_fn(i)
    for i in range(len(gtzan_encoded["train"].features["label"].names))
}
label2id = {v: k for k, v in id2label.items()}

id2label["7"]
```


## Ajuste fino do modelo

Usaremos a classe `Trainer` de 🤗 Transformers. Como vimos em outros capítulos, ela é uma API de alto nível para os cenários de treinamento mais comuns. Aqui, faremos o ajuste fino no GTZAN. Primeiro, carregamos o modelo com `AutoModelForAudioClassification`, que adiciona automaticamente a cabeça de classificação adequada ao DistilHuBERT pré-treinado. Vamos instanciá-lo:

```python
from transformers import AutoModelForAudioClassification

num_labels = len(id2label)

model = AutoModelForAudioClassification.from_pretrained(
    model_id,
    num_labels=num_labels,
    label2id=label2id,
    id2label=id2label,
)
```

Recomendamos fortemente enviar checkpoints diretamente ao [Hugging Face Hub](https://huggingface.co/) durante o treinamento. O Hub oferece:

- Controle de versão integrado, para que nenhum checkpoint se perca durante o treinamento.
- Logs do TensorBoard, para acompanhar métricas importantes.
- Fichas de modelos, para documentar sua função e os casos de uso previstos.
- Comunidade, facilitando o compartilhamento e a colaboração! 🤗

É simples conectar o notebook ao Hub: basta informar seu token de autenticação quando solicitado. Encontre seu token [aqui](https://huggingface.co/settings/tokens):

A próxima etapa é definir os argumentos de treinamento, incluindo tamanho do lote, etapas de acumulação de gradientes, número de épocas e taxa de aprendizado:

```python
from transformers import TrainingArguments

model_name = model_id.split("/")[-1]
batch_size = 8
gradient_accumulation_steps = 1
num_train_epochs = 10

training_args = TrainingArguments(
    f"{model_name}-finetuned-gtzan",
    eval_strategy="epoch",
    save_strategy="epoch",
    learning_rate=5e-5,
    per_device_train_batch_size=batch_size,
    gradient_accumulation_steps=gradient_accumulation_steps,
    per_device_eval_batch_size=batch_size,
    num_train_epochs=num_train_epochs,
    warmup_steps=100,
    logging_steps=5,
    load_best_model_at_end=True,
    metric_for_best_model="accuracy",
    fp16=True,
    push_to_hub=True,
)
```

<Tip warning={true}>

    Definimos <code>push_to_hub=True</code> para enviar automaticamente os checkpoints ajustados durante o treinamento. Se não quiser enviá-los ao Hub, use <code>False</code>.

</Tip>

Por último, definimos as métricas. Como o conjunto é balanceado, usaremos acurácia e a carregaremos com 🤗 Evaluate:

```python
import evaluate
import numpy as np

metric = evaluate.load("accuracy")


def compute_metrics(eval_pred):
    """Computes accuracy on a batch of predictions"""
    predictions = np.argmax(eval_pred.predictions, axis=1)
    return metric.compute(predictions=predictions, references=eval_pred.label_ids)
```

Temos todas as partes! Vamos instanciar `Trainer` e treinar o modelo:

```python
from transformers import Trainer

trainer = Trainer(
    model,
    training_args,
    train_dataset=gtzan_encoded["train"],
    eval_dataset=gtzan_encoded["test"],
    tokenizer=feature_extractor,
    compute_metrics=compute_metrics,
)

trainer.train()
```

<Tip warning={true}>

Dependendo da GPU, você pode encontrar um erro CUDA de falta de memória, <code>out-of-memory</code>, ao iniciar o treinamento. Nesse caso, reduza <code>batch_size</code> progressivamente pela metade e use [<code>gradient_accumulation_steps</code>](https://huggingface.co/docs/transformers/main_classes/trainer#transformers.TrainingArguments.gradient_accumulation_steps) para compensar.

</Tip>

Podemos enviar automaticamente nosso checkpoint ao ranking ao publicar os resultados no Hub, definindo os argumentos nomeados apropriados, ou kwargs. Ajuste esses valores ao conjunto, idioma e nome de modelo que estiver usando:
