# Pré-processamento de um conjunto de dados de áudio

Carregar um conjunto de dados com 🤗 Datasets é só metade da diversão. Para usá-lo no treinamento de um modelo ou na inferência, você precisará primeiro pré-processar os dados. Em geral, isso envolve as seguintes etapas:

* Reamostrar os dados de áudio.
* Filtrar o conjunto de dados.
* Converter os dados de áudio para a entrada esperada pelo modelo.

## Reamostragem dos dados de áudio

A função `load_dataset` baixa os exemplos de áudio com a taxa de amostragem com que foram publicados. Essa taxa nem sempre é a esperada pelo modelo que você pretende treinar ou usar na inferência. Se as taxas forem diferentes, você pode reamostrar o áudio para a taxa esperada pelo modelo.

A maioria dos modelos pré-treinados disponíveis foi pré-treinada com conjuntos de dados de áudio a uma taxa de amostragem de 16 kHz. Ao explorar o conjunto MINDS-14, você pode ter notado que sua taxa é de 8 kHz, o que significa que provavelmente precisaremos aumentá-la.

Para isso, use o método `cast_column` de 🤗 Datasets. Essa operação não modifica o áudio diretamente; em vez disso, instrui a biblioteca a reamostrar os exemplos sob demanda, quando forem carregados. O código a seguir define a taxa de amostragem como 16 kHz:

```py
from datasets import Audio

minds = minds.cast_column("audio", Audio(sampling_rate=16_000))
```

Carregue novamente o primeiro exemplo de áudio do conjunto MINDS-14 e confira se ele foi reamostrado para a taxa de amostragem desejada, indicada por `sampling_rate`:

<Tip>
💡 Um pouco mais sobre reamostragem: se um sinal de áudio foi amostrado a 8 kHz, com 8.000 amostras por segundo, sabemos que o áudio não contém frequências acima de 4 kHz. Isso é garantido pelo teorema de amostragem de Nyquist. Assim, podemos ter certeza de que o sinal contínuo original descreve uma curva suave entre os pontos de amostragem. Aumentar a taxa de amostragem consiste em calcular valores adicionais entre as amostras existentes, aproximando essa curva. Para reduzir a taxa, porém, precisamos primeiro filtrar as frequências que excederiam o novo limite de Nyquist, antes de estimar os novos pontos de amostragem. Em outras palavras, não podemos reduzir a taxa pela metade simplesmente descartando uma amostra a cada duas: isso cria distorções no sinal chamadas de aliases. Reamostrar corretamente é uma tarefa complexa, que é melhor deixar a cargo de bibliotecas bem testadas, como librosa ou 🤗 Datasets.
</Tip>

## Filtragem do conjunto de dados

Você pode precisar filtrar os dados com base em determinados critérios. Um caso comum é limitar a duração dos exemplos de áudio. Por exemplo, podemos excluir exemplos com mais de 20 s para evitar erros de falta de memória durante o treinamento de um modelo.

Podemos fazer isso com o método `filter` de 🤗 Datasets, passando a ele uma função com a lógica de filtragem. Vamos começar escrevendo uma função que indique quais exemplos manter e quais descartar. Essa função, `is_audio_length_in_range`, retorna `True` se a amostra tiver menos de 20 s e `False` se tiver mais de 20 s.

```py
MAX_DURATION_IN_SECONDS = 20.0


def is_audio_length_in_range(input_length):
    return input_length < MAX_DURATION_IN_SECONDS
```

A função de filtragem pode ser aplicada a uma coluna do conjunto de dados, mas esse conjunto não tem uma coluna com a duração dos áudios. Podemos criar essa coluna, filtrar com base em seus valores e depois removê-la.

```py
# use librosa to get example's duration from the audio file
new_column = [
    librosa.get_duration(y=x["array"], sr=x["sampling_rate"]) for x in minds["audio"]
]
minds = minds.add_column("duration", new_column)

# use 🤗 Datasets' `filter` method to apply the filtering function
minds = minds.filter(is_audio_length_in_range, input_columns=["duration"])

# remove the temporary helper column
minds = minds.remove_columns(["duration"])
minds
```

**Saída:**
```out
Dataset({features: ["path", "audio", "transcription", "intent_class"], num_rows: 624})
```

Podemos conferir que a filtragem reduziu o conjunto de 654 para 624 exemplos.

## Pré-processamento dos dados de áudio

Um dos aspectos mais desafiadores do trabalho com conjuntos de dados de áudio é preparar os dados no formato correto para treinar o modelo. Como vimos, o áudio bruto é representado por um array de valores de amostras. No entanto, modelos pré-treinados, tanto para inferência quanto para ajuste fino em sua tarefa, esperam que esses dados sejam convertidos em características de entrada. Os requisitos dessas características podem variar de um modelo para outro: dependem da arquitetura do modelo e dos dados usados em seu pré-treinamento. A boa notícia é que 🤗 Transformers oferece uma classe de extrator de características para cada modelo de áudio compatível, capaz de converter o áudio bruto nas características de entrada esperadas.

O que um extrator de características faz com o áudio bruto? Vamos examinar o extrator de características do [Whisper](https://huggingface.co/papers/2212.04356) para entender algumas transformações comuns na extração de características. Whisper é um modelo pré-treinado para reconhecimento automático de fala (ASR), publicado em setembro de 2022 por Alec Radford e colaboradores, da OpenAI.

Primeiro, o extrator de características do Whisper preenche ou trunca um lote de exemplos de áudio para que todos tenham 30 s de duração na entrada. Exemplos mais curtos são preenchidos até 30 s com zeros no final da sequência; zeros em um sinal de áudio correspondem à ausência de sinal, ou silêncio. Exemplos com mais de 30 s são truncados para 30 s. Como todos os elementos do lote são preenchidos ou truncados para um comprimento máximo no espaço de entrada, não é necessária uma máscara de atenção. Whisper se diferencia nesse aspecto: a maioria dos outros modelos de áudio exige uma máscara de atenção que indique onde as sequências foram preenchidas e, portanto, onde devem ser ignoradas pelo mecanismo de autoatenção. Whisper é treinado para operar sem máscara de atenção e deduzir diretamente dos sinais de fala quais entradas ignorar.

A segunda operação do extrator de características do Whisper é converter os arrays de áudio preenchidos em espectrogramas log-mel. Como vimos, esses espectrogramas descrevem como as frequências de um sinal mudam ao longo do tempo. Elas são expressas na escala mel, enquanto a intensidade é medida em decibéis — a parte “log” — para que frequências e amplitudes representem melhor a audição humana.

Todas essas transformações podem ser aplicadas ao áudio bruto com poucas linhas de código. Vamos carregar o extrator de características de um checkpoint pré-treinado do Whisper para deixá-lo pronto para nossos dados:

```py
from transformers import WhisperFeatureExtractor

feature_extractor = WhisperFeatureExtractor.from_pretrained("openai/whisper-small")
```

Em seguida, escreva uma função para pré-processar um único exemplo de áudio, passando-o pelo `feature_extractor`.

```py
def prepare_dataset(example):
    audio = example["audio"]

    if audio["sampling_rate"] != 16000:
        audio_array = librosa.resample(
            audio["array"], orig_sr=audio["sampling_rate"], target_sr=16000
        )
        audio = {"array": audio_array, "sampling_rate": 16000}

    features = feature_extractor(
        audio["array"], sampling_rate=audio["sampling_rate"], padding=True
    )
    return features
```

Podemos aplicar a função de preparação de dados a todos os exemplos de treinamento usando o método `map` de 🤗 Datasets:

```py
minds = minds.map(prepare_dataset)
minds
```

**Saída:**
```out
Dataset(
    {
        features: ["path", "audio", "transcription", "intent_class", "input_features"],
        num_rows: 624,
    }
)
```

Pronto: agora temos espectrogramas log-mel no campo `input_features` do conjunto de dados.

Vamos visualizar um dos exemplos do conjunto `minds`:

```py
import numpy as np

example = minds[0]
input_features = example["input_features"]

plt.figure().set_figwidth(12)

    np.asarray(input_features[0]),
    x_axis="time",
    y_axis="mel",

```

Agora você pode ver como fica a entrada de áudio do modelo Whisper após o pré-processamento.

A classe de extrator de características do modelo transforma o áudio bruto no formato esperado pelo modelo. No entanto, muitas tarefas que envolvem áudio são multimodais, como o reconhecimento de fala. Nesses casos, 🤗 Transformers também oferece tokenizadores específicos de cada modelo para processar as entradas de texto. Para se aprofundar em tokenizadores, consulte nosso [curso de NLP](https://huggingface.co/course/chapter2/4).

Você pode carregar o extrator de características e o tokenizador do Whisper e de outros modelos multimodais separadamente, ou carregar ambos por meio de um processador. Para simplificar ainda mais, use `AutoProcessor` para carregar o extrator de características e o processador de um modelo a partir de um checkpoint:

```py
from transformers import AutoProcessor

processor = AutoProcessor.from_pretrained("openai/whisper-small")
```

Aqui mostramos as etapas fundamentais de preparação de dados. Naturalmente, dados próprios podem exigir pré-processamento mais complexo. Nesse caso, você pode ampliar a função `prepare_dataset` para realizar as transformações necessárias. Com 🤗 Datasets, se você consegue escrever a transformação como uma função Python, pode [aplicá-la](https://huggingface.co/docs/datasets/audio_process) ao seu conjunto de dados!
